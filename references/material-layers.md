# 固有色与光影分层

所有项目都将制作范围内的固有色与光影分开，保存在可编辑母版中。固有色是对材质本色的合理解释，保留原画的颜色变化、渐变和图案，不要求从单张图恢复唯一的物理反射率。按对象和表面归属拆层，不按 RGB 相近程度分割。

## 图层职责

| `paint_role` | 内容 |
| --- | --- |
| `base_color` | 完整材质底色或稳定色面，包含约定动作需要的隐藏延伸，通常随所属部件运动。 |
| `linework` | 属于本部件的轮廓、结构线及抗锯齿。 |
| `texture` | 表面图案与材质细节。 |
| `form_shadow` | 表面体积明暗，与接收面相连。 |
| `cast_shadow` | 其他对象投下的阴影，记录投射者、接收面和相对运动处理方式。 |
| `highlight` | 表面高光与反光，记录接收面和随动要求。 |
| `composite` | 普通图层版中已合成的动画绘制段，不作为固有色已分离的证据。 |

只建立画面实际存在的内容层，不为凑齐类别创建空图层；固有色与存在的光影必须分开。描线、纹理及高光保留各自编辑职责。同材质跨越多个运动部件时，可以共享材质定义，但不能把它们的底色粘成一个移动层。多种稳定本色可分为可编辑色面，不按每个颜色值建层。

完整底片的范围取决于对象表面，不能用投影轮廓裁出孔洞。纯底色由去光照重建得到；原画表现通过底色和光影重新组合检查。需要保留带阴影的完整部件时，从母版另作合成，不同时叠加同一份烘焙阴影和独立阴影。

## 数据约定

`plan.json` 的 `materials` 登记材质，`drawing_specs` 登记各绘制层；生产时将绘制字段写入 `project.json` 的 `parts[]`。例如：

```json
{
  "materials": [{
    "id": "surface", "name": "目标表面",
    "base_color_note": "依据本表面的未受光影区域重建本色",
    "source_evidence": "填写实际观察的原图区域",
    "base_drawings": ["part_base"]
  }],
  "drawing_specs": {
    "part_base": {"material_id": "surface", "paint_role": "base_color", "order": 10},
    "part_shade": {
      "material_id": "surface", "paint_role": "form_shadow", "order": 11,
      "receiver_id": "part_base"
    }
  }
}
```

这是字段示例，绘制 ID 须存在于实际部件清单。`base_drawings` 引用同材质的底色层；纹理、明暗、高光和投影用 `receiver_id` 指向相应底色。投影另有 `caster_ids` 和具体的 `motion_policy`；画外或无法确定的投射者用 `caster_note` 说明。

文字策略必须落实到图层、状态或控制中。记录投影与接收面、投射者的关系，双方变化时复查。脚本验证引用，不会自动生成阴影或实现随动。背景也按此分层；统计角色轮廓时排除背景 alpha。

## 混合与交付

内置复合与 `build_psd.jsx` 只处理普通 RGBA 混合。需要剪贴、蒙版、Multiply 等效果时，在图像软件内建立并检查真实关系；不要给脚本增加它不执行的字段后宣称已生效。

母版保留这些编辑层。普通图层版按动画绘制段合成，仍保留需要相对移动的部件及光影。两份文件的对应状态应一致，导出方法见[PSD 导出](psd-export.md)。独立显示底色、恢复光影、移动接收面与投射者的检查，统一按[验收标准](quality.md)执行。
