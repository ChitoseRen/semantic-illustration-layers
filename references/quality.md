# 验收与桌面检查

本文件统一定义通过标准。方案确认决定制作范围；实际画面检查决定质量。所有约定部件、绘制段和状态都在检查清单内，缺失或未检查的内容保持 `pending`。修复后复查相关项，不以增加图层数、正常帧数或缩小动作范围提高通过率。

## 部件通过条件

| 记录字段 | 必须看到的结果 |
| --- | --- |
| `object_semantics` | 部件的结构、朝向、比例及线条归属正确，没有借用邻件或背景冒充本体。 |
| `hidden_completion` | 根部、末端及动作会露出的隐藏区域完整，与可见本体连续，没有生成画框造成的裁断或内部缺块。 |
| `no_foreign_pixels` | 无邻件、旧五官、背景残片和重复遮挡线；真实结构线与应有投影仍在正确图层。 |
| `alpha_edges` | 完整轮廓在黑底、白底、透明棋盘和实际背景上清晰；抗锯齿、细丝、笔触与孔洞自然，无新增碎边、色晕或透底。 |
| `static_assembly` | 关闭原图参考后，默认姿态的形体、位置、五官布局、色彩和光影与原图对应；接口无空隙、双线及明显色缝。 |
| `required_motion` | 约定相对动作、端点、中间姿态、替换状态及恢复均衔接正常，不露切边、残影或缺口。 |

同一逻辑部件的所有必交绘制段和状态均满足六项条件，才算该部件通过。前后遮挡段可以有局部切口，但须与完整底片共同运动，切口不能在必测姿态中露出。原图有意出画的边界单独记录；需要移入画面的部分应提前补全或明确限制。

固有色单独显示时覆盖完整所属表面，能独立选择、开关和移动；重新合回线条与光影后还原原画。投影同时检查投射者、接收面和实际随动策略，不能用不透明阴影掩盖底色孔洞。

## 如何查看

使用当前环境可用的桌面控制器并读取对应技能。在明确的图像软件窗口中执行图层开关、缩放、切换与移动，再观察当前画面；保留用户原文档，用副本进行可能改变内容的诊断，完成后恢复默认状态。

| 时机 | 检查内容 |
| --- | --- |
| 规划与生产选区 | 原图全图、交界放大、相邻单层和局部回拼，确认像素归属与补画范围。 |
| 代表性难点、每批组装和修复后 | 同坐标原图／当前复合，完整单件与底片，及时复查受影响邻件。 |
| 动作与状态检查 | 相邻件相对运动、底色独立显示及移动、全部约定状态、端点和恢复。 |
| 最终保存后 | 重开两份实际 PSD，验证可编辑性、普通像素层、参考层隐藏和同状态复合，再恢复并核对保存内容。 |

原图和候选保持相同缩放、位置、画布及色彩解释。原尺寸看整体，放大查看轮廓和接缝；叠加或闪切帮助定位，结束时关闭原图参考，确认画面来自候选本身。独立检查要扫查完整轮廓，不能只看缩略图或被遮住的接头。

脚本和 Photoshop 接口可准备图层状态、对照或动作预览；仅查看导出 PNG、打开文件或保存截图，不能代替上述桌面操作与判断。控制器失败时按其技能尝试已有兼容路径，仍不可用则保存可审阅资产并注明“桌面视觉验收未完成”，不自行改写完成条件。

## 记录与复查

每项记录 `pass`／`fail`／`pending`、实际文件版本或哈希、检查区域、状态／姿态、观察结论和证据位置。结论指出具体对象及缺陷；工具没有截图落盘能力时，保留可追溯调用，不编造截图路径。程序只检查记录是否匹配，不替代观察。

修改本件后复查本件；修改邻件、状态、层序或运动祖先后复查受影响接口和后代动作。保留仍有效的独立边缘检查与历史失败，不给旧结论换上当前哈希后直接复用。`relations.dependency_fingerprint` 可绑定依赖，详见[数据格式](schema.md)。

## 测量怎样使用

`fidelity_report.py`、`alignment_review.py` 和 `appearance_check.py` 提供位置、像素差异、轮廓及接缝诊断。使用相同背景、画布和比较区域，不额外挪动候选来降低误差。地标拟合点与独立核验点分开；缺少真值、蒙版或观察依据时报告不可测。

归属明确的原像素保留区检查 RGB 与透明度是否被改变；去光照底色按材质分层要求检查，隐藏区不以原图遮挡物的颜色为真值。颜色校正和内部融合要保留未处理版本，只有实际对照改善时采用。

容差按原图分辨率和用途确定。全图平均值不能抵扣局部破坏，MAE 也不是“还原百分比”。质量结论以六项检查和当前画面为准。

交付说明列出通过、未完成和使用限制；记录可核实的生成调用及耗时。没有可比记录就不声称节省时间、费用或达到某个成功率。
